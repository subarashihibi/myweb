如何在这里写一篇新文章

这个站不使用任何框架与构建工具：一篇文章就是一个 HTML 文件，外加在索引里登记一行。 以下是从起草到发布的完整流程，以及可以使用的排版样式清单。

一、目录结构

.
├── index.html            首页（近期文章）
├── archive.html          归档：年份分组、关键词检索、主题与年份筛选
├── topics.html           主题与标签总览；?c=主题 或 ?t=标签 可筛出篇目
├── about.html            留言板（Guestbook）＋站点说明
├── write.html            写作台：Markdown 草稿 → 实时预览 → 生成 HTML
├── assets/
│   ├── site.css          全部样式（配色、字体、版式都在这里）
│   ├── index.js          ★ 站点数据：站名、页脚署名、文章索引
│   └── render.js         页头页脚注入、主题切换、目录、列表与筛选
└── posts/
    ├── _template.html    文章模板（复制它开始新文章）
    ├── _template.md      纯 Markdown 草稿模板
    └── writing-guide.html  本页（写作与发布说明）

二、写一篇新文章（四步）

第 1 步：起文件名

把 posts/_template.html 复制一份，改成新的文件名。 规则：全小写、单词间用连字符、只用 ASCII 字符，文件名就是网址。

  • ✅ kant-copernican-turn.html
  • ✅ hume-causation.html
  • ❌ 康德.md（中文与空格在网址里会出现乱码）

第 2 步：改模板中标了「⟵ 改这里」的四处

  1. <title> 与 <meta name="description">：标题与提要，用于浏览器标签与搜索摘要。
  2. .article__meta 里的日期、主题、标签。
  3. 正文：在 <div class="article__body" id="article-body"> 内部写内容。
  4. 文末的上一篇 / 下一篇链接。

第 3 步：在索引里登记一行

打开 assets/index.js，在 SITE.posts 数组的最前面 插入一条记录（最新的放最上面）。file 必须与第 1 步的文件名完全一致。 

{
  file: "posts/kant-copernican-turn.html",
  title: "康德的哥白尼式革命",
  date: "2026-03-01",                  // 必须是 YYYY-MM-DD
  category: "认识论",                  // 一篇只归一个主题
  tags: ["康德", "先验", "知识论"],     // 可多个，显示为 #标签
  summary: "一句话提要，出现在首页与归档列表里。",
  words: 1234                        // 字数，见下方说明
}

为什么必须手工登记

浏览器出于安全限制，无法从一个用 file:// 双击打开的页面里读取目录列表。 因此文章索引写在 assets/index.js 里。好处是：站点可以完全离线、双击即用， 也能直接丢到任何静态托管上，无需构建。

关于字数

文章页与列表里的「N words」取自索引的 words 字段，由 assets/render.js 自动填入，正文里不用手写。 统计口径是「CJK 逐字 + 西文按词」，附录（.footnotes）不计入。 改完文章后跑一次自检即可拿到应填的数值： 

python tools/check.py
# 若字数对不上，报错信息里会直接给出实际统计值，例如：
#   字数不一致：posts/xxx.html
#       索引 index.js：1234
#       实际统计：1288

第 4 步：打开检查

双击 index.html，确认新文章出现在「近期文字」；再点 archive.html 下「主题」筛选，确认分类正确。若文章没出现，九成是 file 路径写错或少了逗号。

三、用 Markdown 起草

打开 write.html，左侧写 Markdown，右侧实时看到接近成品的排版。 它支持标题、引文、列表、表格、脚注、题词、分隔花星与行内强调。 定稿后点「生成 HTML」，把生成的片段替换掉模板中 .article__body 里的内容即可。

草稿会自动保存在浏览器本地（localStorage），关掉页面也不会丢。 也可以点「下载 .md」，把草稿作为 posts/你的文件名.md 留档。

四、可用的排版样式

全部样式定义在 assets/site.css，下面是哲学写作里最常用的几件。

提要与题词

提要（.article__abstract）是文章标题下的摘要，用左侧细线标出；题词（.epigraph）居中、无引号装饰。

两样东西，越经常越持久地思索，就越使心中充满常新而日增的赞叹与敬畏。

—— 康德《实践理性批判》结论

引文与出处

用 <blockquote> 包住引文，出处放在 <cite> 里，会自动排成小字、非斜体。

存在者存在，不存在者不存在。

巴门尼德，残篇 DK 28 B 6

术语对照

用 <dl>/<dt>/<dd> 区分容易混淆的一组概念，比表格更适合长解释。

a priori（先天的）
不依赖经验而成立，如「一切变化都有原因」。
a posteriori（后天的）
必须依赖经验才能成立，如「今天下雨」。

要点框、脚注、分隔符

  • 要点框：<div class="notice">，适合放关键主张或待解决问题，一节最多用一次。
  • 脚注：正文用 <a class="fn-ref" href="#fn1">[1]</a>，文末用 <section class="footnotes">。
  • 分隔符：单独一行的 <hr> 会显示成一枚花星 ❋，用于分隔论证的两种走向。
  • 表格：<table> 自带发丝线，适合对比两种立场或列出论证步骤。

五、这个站的内容约定

  • 一篇一个主题：主题（category）只能选一个，用于归档归类；其余用标签（tags）叠加，最多四个。
  • 引用随文夹注：古典著作给通行编码（《形而上学》1003a21），现代著作给书名与页码，细节在脚注。
  • 术语附原文：第一次出现的核心术语加括号原文，如 Dasein（此在）、elenchus（诘问）。
  • 写清论证而非立场：至少交代这个主张要解决什么问题、反对者会怎么反驳。
  • 长度不设限：一千五百字到四千字之间读起来最舒服，长文请用小节标题分段，右侧目录会自动生成。

六、改成你自己的站

  • 站名与署名：assets/index.js 顶部的 SITE 对象：title、tagline、author、email、copyrightFrom。
  • 配色：assets/site.css 开头的 :root 变量。米白底是 --paper，墨色是 --ink，强调色是 --accent；html[data-theme="dark"] 里是夜间配色。
  • 字体：--serif 与 --sans 两个变量，均为系统字体栈，不加载任何外部字体。
  • 导航：assets/render.js 里的 NAV 数组。
  • 页脚：renderFooter() 函数。
  • 留言板（Guestbook）页的文字：改 about.html，并把其中的「留言板尚未接通」提示框删掉或换成真实联系方式。

七、发布到网上

整个目录就是成品，没有构建步骤。任选其一：

  • GitHub Pages：把目录推到仓库，Settings → Pages 选分支根目录即可。
  • Netlify / Vercel / Cloudflare Pages：拖拽整个文件夹上传，秒级完成。
  • 任意静态托管或对象存储：直接上传，无需服务器端程序。

注意：所有内部链接都是相对路径（../assets/…、topics.html?c=…）， 因此放在子目录（如 example.com/blog/）也能正常工作。

写作建议

先写提要。如果无法用三句话说明这篇要解决什么，说明问题还没有成形。 剩下的部分会快得多。
